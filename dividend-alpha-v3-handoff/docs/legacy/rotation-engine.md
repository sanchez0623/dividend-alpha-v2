# 04 · 轮动引擎设计（★ 策略范式升级后的核心模块）

> ⚠️ **整篇已证伪，仅作历史档案**：轮动范式已永久关闭（见 `research/REPORT3/5/6/9.md`）。
> 唯一仍有效的是 §2.3「除权除息机械跳变修正」。以 [`IMPLEMENTATION.md`](./IMPLEMENTATION.md) 为准。


> **范式变更**：原设计是「持有型 Core-Satellite」（买入高股息不动 + 做T增强）。
> 你的真实意图是「**轮动型**」：**股息率高（价低）时买入，股息率走低（价涨）时卖出，换到另一批股息率仍处高位的标的，循环往复。**
> 这不是参数调整，是策略本体的改变。本文档定义轮动引擎，并列出原架构中必须修改的部分。

---

## 1. 范式对比：改了什么

| 维度 | 原设计（持有型） | 新设计（轮动型） | 影响 |
|---|---|---|---|
| 收益主要来源 | 股息 + 估值修复 | **★ 轮动价差** | 轮动层成为第一主角 |
| 核心仓语义 | 锁仓吃息，永不动 | **可卖出**，触发即换 | `core_ratio` 语义失效 |
| 持有周期 | 多年（>1年，免红利税） | 数月 ~ 1-2年 | **红利税成为真实成本** |
| 换手率 | 极低（季度再平衡） | 高 | 成本模型权重上升 |
| 主要风险 | 个股暴雷 | **★ 卖飞 / 无股可换 / whipsaw** | 需新增三类风控 |
| 增强层（做T） | 依托稳定底仓 | 底仓在变，**做T基础不稳** | 需重新定义（见 §7） |

## 2. 轮动信号：股息率历史分位（核心因子）

### 2.1 定义

```
div_yield_pctile(symbol, t, window)
  = 当前股息率在 [t-window, t] 区间内自身历史股息率序列中的百分位
```

- **高百分位（>70%）** = 股息率处于自身历史高位 = **股价处于相对低位** → 买入
- **低百分位（<30%）** = 股息率处于自身历史低位 = **股价已被推高** → 卖出

### 2.2 ★ 多窗口冲突处理（银行就是活案例）

| 窗口 | 银行当前 PB 分位 | 结论 |
|---|---|---|
| 近 10 年 | 26% – 45% | 还在低位 |
| 近 5 年 | **72%** | 已偏高 |
| 近 3 年 | **80%** | 高位 |
| 近 2 年 | **91%** | 极高位 |

**同一标的，窗口不同结论完全相反。** 必须显式定义冲突策略：

```yaml
div_yield_pctile:
  windows: [3, 5, 10]
  conflict_policy: conservative   # conservative | vote | weighted
  # conservative（默认）：取最高窗口要求，宁可不换，防过早换出
  #   例：银行 3y=80 / 5y=72 / 10y=36 → 判定为「已修复」，发出减仓信号
```

### 2.3 ★ 除权除息的机械跳变（必须修正，否则信号全假）

**陷阱**：A 股年度分红除权日集中在 **5-7 月**。除权当日股价下跌 D，但 TTM 股息（分子）不变：

```
除权前：股价 100，TTM股息 5.00 → 股息率 5.00%
除权后：股价  95，TTM股息 5.00 → 股息率 5.26%   ← 机械跳升 +0.26pct
```

后果：**每年 6-7 月，全市场高股息股会集体发出假的"低位"买入信号**，正好和分红季重合，极具欺骗性。

**修正方案**（三选一，推荐 A）：
- **A（推荐）**：分位序列统一使用**前复权价格**计算股息率 → 除权前后连续，无跳变
- **B**：使用「除权前一日股息」对齐，即除权日当天用 `close + D` 还原
- **C**：除权日前后 5 个交易日**冻结**该标的的轮动信号

```yaml
rotation:
  ex_dividend_adjust: forward_adjusted_price   # A 方案
  signal_freeze_days_around_ex: 3              # 额外冻结，双保险
```

## 3. ★ 新增：股息率变动归因（防价值陷阱的关键升级）

同样是股息率 6%，成因天差地别。**原文档的四重过滤挡不住 C/D 两类**，必须显式拆解：

| 类型 | 分子（分红 D） | 分母（股价 P） | 判定 | 典型例子 |
|---|---|---|---|---|
| **A 分红驱动** | ↑↑ | → | ✅ 优质，可持有不换 | 银行 2024-2026（分红比例上调、中期分红常态化） |
| **B 股价超跌** | → | ↓↓ | ✅ **你的核心机会** | 2023 年的银行 |
| **C 崩塌陷阱** | ↓ | ↓↓↓ | ❌ 危险 | 盈利下滑但股价跌更多 |
| **D 周期顶陷阱** | ↑↑（周期高点） | → | ❌ 危险 | 煤炭 2021-2022 盈利顶部 |

```yaml
div_yield_attribution:
  lookback_months: 12
  # 硬性排除
  reject_if:
    - profit_down_and_price_down_faster      # C 类
    - payout_ratio_gt: 90                    # D 类（吃老本/周期顶）
    - dividend_amount_declined_20pct: true
  # 偏好
  prefer: [numerator_driven, denominator_driven]
```

## 4. ★ 新增：换出规则（防止"卖掉鲜花浇灌杂草"）

**这是轮动策略最大的行为陷阱**：无条件"涨了就卖"会让你**系统性地剪掉赢家、留住输家**。

一只股票股息率变低，有两种可能：
1. 股价被推高、透支未来 → 该卖 ✅
2. **基本面改善、进入长期上升通道** → 卖了就永久损失 ❌

必须加保护：

```yaml
rotation:
  exit_rules:
    # 触发条件（主信号）
    trigger:
      div_yield_pctile_5y_below: 30.0
    # ★ 保护条款：满足任一则不卖
    hold_overrides:
      - name: trend_guard          # 趋势保护
        condition: "close > ma60 AND ma60_slope_60d > 0 AND div_yield > 3.0"
        action: hold_half          # 只减半，不清仓
      - name: dividend_growth      # 分红增长保护
        condition: "dividend_amount_yoy > 10%"
        action: hold_half
      - name: tax_guard            # ★ 红利税保护（见 §5）
        condition: "holding_days < 335"
        action: defer              # 推迟到满 1 年再卖，税率 10% → 0%
    # 观察期，避免单日噪声触发
    confirm_days: 20
    action_on_confirm: trim_to_half   # 减半而非清仓，保留仓位继续吃息
```

## 5. ★ 新增：红利税优化（轮动独有成本）

轮动会让持股期从「多年」变成「数月」，红利税从 0% 变成 10-20%。这是**原架构完全没有的成本项**。

| 持股期 | 税率 | 年化税负（假设股息率 5%） |
|---|---|---|
| ≤ 1 个月 | **20%** | 1.00% |
| 1 个月 – 1 年 | **10%** | 0.50% |
| **> 1 年** | **0%** | **0.00%** |

**两条硬规则**：

1. **除权日持有约束**：卖出时若临近除权日，**持有过除权日再卖**。否则白白损失一整年分红（4-6%）去换几个点的轮动价差，必亏。
2. **满年优先**：持股 > 335 天时，若轮动信号不强烈（分位 > 20%），推迟到满 1 年再卖出，税率直接 10% → 0%。

```yaml
dividend_tax_optimization:
  enabled: true
  capture_window:
    # 距除权日 N 天内禁止卖出（除非触发硬止损）
    no_sell_days_before_ex: 20
    require_hold_through_ex: true
  full_year_bonus:
    # 持股 > 335 天，信号强度 < 阈值时推迟卖出
    min_holding_days: 335
    defer_if_pctile_above: 20.0
  fifo_sell_order: longest_first   # ★ 卖出时优先出最早批次（已满1年，税率0）
```

## 6. 换手预算与成本上限（★ 决定能否达成 15%）

轮动成本 = 换手成本 + 红利税。实测：

| 年换手率 | 个股成本 | ETF 成本 |
|---|---|---|
| 100% | 0.30% | 0.15% |
| 200% | 0.60% | 0.30% |
| 400% | 1.20% | 0.60% |
| 600% | 1.80% | 0.90% |

**达成 15% 所需轮动层毛收益**（股息 4.5% 打底）：

| 轮动年成本 | 轮动层毛收益要求 | 若做T再贡献 2% |
|---|---|---|
| 0.4% | **10.9%** | 8.9% |
| 0.8% | **11.3%** | 9.3% |
| 1.2% | **11.7%** | 9.7% |
| 2.0% | **12.5%** | 10.5% |

> ⚠️ **诚实结论**：轮动层需要贡献 **9-12% 毛收益**才能达成 15%。这是一个相当高的要求——它本质上是要求你持续做对**板块层面的均值回归择时**。

**因此必须设硬约束**：

```yaml
rotation:
  turnover_budget:
    max_annual_turnover: 2.0        # 年换手率上限 200%（成本 ~0.6%）★
    max_positions_changed_per_event: 0.30   # 单次最多换 30%
    min_holding_days: 90            # ★ 最短持股 90 天（控税 + 控换手）
    cooldown_days_same_symbol: 180  # 卖出后 180 天内不得买回，防 whipsaw
  trigger_mode: threshold           # ★ 阈值触发，非日历触发
  # threshold：只在分位穿越阈值时换 → 换手低、成本低
  # calendar：定期换 → 换手高、成本失控（不推荐）
```

## 7. 增强层（做T）的定位必须重构

**冲突**：轮动型策略下，标的每几个月换一批，做T所依赖的"稳定底仓"不存在了。

**三种方案**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 做T只在**红利ETF**（510880/515180）上做，与个股轮动完全分离 | 成本减半（免印花税）、天然分散、底仓稳定 | 不改变个股持仓 |
| B | 做T只在当前持仓中**持股 > 90 天**的标的上做 | 利用现有底仓 | 底仓会变，需频繁重配 |
| C | 暂时关闭做T，先把轮动层跑通 | 聚焦、降低复杂度 | 少一层收益 |

**建议：P0-P2 阶段采用方案 A 或 C。** 轮动层的复杂度已经很高，同时叠加做T极易相互干扰、且无法归因。等轮动层验证有效后（B7 显著跑赢 B2）再叠加做T。

## 8. 轮动专用风险：无股可换

**问题**：当整个红利风格都被推高（如 2025 年 7 月的银行），可能**找不到足够多的"股息率处于自身高位"的标的**。此时系统必须明确怎么办，否则会强行买入不合格标的。

```yaml
rotation:
  underfill_policy:
    min_qualified_candidates: 10    # 合格候选少于 10 只时启动
    action_sequence:
      - hold_current              # 1. 优先持有现有仓位（不动）
      - add_etf                   # 2. 补充红利ETF（510880/515180/512890）
      - hold_cash                 # 3. 持币等待
    max_cash_ratio: 0.30          # 现金上限 30%，超出现金拖累过大
    # ★ 记录 cash_drag 指标，用 B9 基准量化这段时间的拖累
```

**配套必须加一个基准 B9（见 §9）**，否则你会把"无股可换导致的空仓"误判为策略失效。

## 9. 基准体系扩充（原 B1-B6 不够了）

| 代码 | 基准 | 新增 | 回答什么问题 |
|---|---|---|---|
| B1 | 集中持有不动 | | 分散是否有用 |
| B2 | 分散持有不动 | | 轮动 vs 不轮动（对照组之一） |
| B3 | 红利指数 | | 是否跑赢被动红利 |
| B4 | 沪深300 | | 是否跑赢市场 |
| **B7** | **★ 股息率分位轮动（无做T）** | ✅ | **轮动层本身是否有效**（最关键） |
| **B8** | **★ 随机轮动对照** | ✅ | 换到**随机**标的、相同频率 → 轮动择时是真 alpha 还是运气 |
| **B9** | **轮动 + 现金拖累** | ✅ | 无股可换时空仓，拖累了多少 |
| B6 | 随机做T对照 | | 做T是否有效（轮动验证后再加） |

### ★ B8 随机轮动对照（本阶段最关键）

与 B7 完全相同：**相同的换手次数、相同的换仓时点、相同的仓位结构**，唯一差别是**换入的标的随机挑选**（从同一候选池中随机取）。

```
B7 − B2 = 轮动层毛贡献
  ├─ ≤ 0                          → ❌ 轮动有害，回到持有型
  ├─ > 0 但 < 成本                → ⚠️ 被换手成本+红利税吃光，降低换手频率
  ├─ > 成本，但 ≈ B8              → ❌ 收益来自"换仓行为本身"而非选股择时
  └─ > 成本，且显著 > B8 (p<0.05) → ✅ 轮动选股真实有效
```

判定门槛：换仓样本 ≥ 50 次（轮动频率低于做T，样本积累慢，需更长回测区间，建议 ≥ 10 年）。

## 11. 修订后的收益拆解

```
目标年化 15%
 ├─ 股息收入        4.0 – 5.0%   （持股期变短，实际到账可能低于"买入不动"）
 ├─ ★ 轮动价差      8.0 – 11.0%  ← 第一主角，需验证
 ├─ 做T增强         0 – 3.0%     ← 第二阶段再加（ETF 做T）
 └─ 成本            -1.0 – -2.0% （换手 0.6% + 红利税 0.5% + 现金拖累 0.3%）
```

> **最重要的一条**：轮动层的收益本质是**板块均值回归的择时收益**。它高度依赖"低估值板块总会回归"这一假设。
> 一旦遇到长期风格切换（如 2021-2023 银行连跌三年），轮动会持续买入"越跌越买"的标的，承受长时间浮亏。
> **核心仓必须是不会被迫卖出的钱**，否则你会在轮动生效前被迫离场。

## 13. 实证检验结果（2026-10，全A 5222 只，2008-2026）

> 完整报告见 `research/REPORT.md`，可复现脚本见 `research/`。

### 核心数字

| 检验 | 结果 |
|---|---|
| IC（股息率5年分位 vs 前向收益） | 3月 +0.025 ／ 6月 +0.034 ／ **12月 +0.055** ／ **24月 +0.096（ICIR 0.95）** |
| 五分组 Q5−Q1（NW 校正） | 12月 +1.83%（t=1.10 不显著）／ **24月 +6.79%（t=1.89）** |
| 控制股息率水平后的分位增量 | 12月 +0.40%（t=0.44）／ **24月 +3.32%（t=2.50 显著）** |
| 分位>70 vs 分位<30 的未来24月收益 | **+24.94% vs +17.44%，差 +7.50%，t=2.95，胜率 77%** |
| B7 轮动+质量过滤 vs B2 持有+质量过滤 | **14.02% vs 10.97%＝+3.05%/年，t=1.17，p=0.243（不显著）** |
| B7 vs B8 随机轮动 | B7 处 **98.3 分位**（换股选择有信息） |
| 年换手 / 年成本 | **54% / 0.16%**（远低于此前估计，成本非主要矛盾） |

### 三条推翻原设计的结论

1. **质量过滤（连续分红≥5年）是轮动的开关**：无此过滤时轮动跑输持有 0.77%；有此过滤时跑赢 3.05%。
2. **趋势保护有害，已删除**：加入后年化 14.02%→10.74%，最大回撤 −24.5%→−33.3%。高股息股涨贵了就该卖，"让利润奔跑"在此不成立。
3. **降频无益**：月频 14.02% > 季频 9.72% > 半年频 10.42%。且换手仅 54%/年，成本压力很小。

### 对收益目标的修正

回测年化 14.02%，但存在**幸存者偏差**（仅当前上市股），现实预期 **11-13%**。
**单靠轮动达不到 15%**，差额需由增强层（做T/波段）补足，而增强层尚未验证。

### 未覆盖的局限（下一步必做）

存活者偏差 ／ 无行业分类（未做行业中性化）／ 无历史 ST 标记 ／ 无 payout ratio（缺 EPS）
／ 区间含 2021-2026 红利牛市 ／ 未模拟涨跌停与停牌。

## 14. 第二轮实证：增强层的重新定义（2026-10）

完整报告见 `research/REPORT2.md`。

### 增强层 = 超跌反弹事件驱动（不是技术做T）
